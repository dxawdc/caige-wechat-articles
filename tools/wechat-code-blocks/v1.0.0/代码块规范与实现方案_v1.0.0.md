# 公众号代码块规范与实现方案

版本：v1.0.0
更新时间：2026-09-15
状态：默认制作基线；通用实现与本地验收通过；客户端效果按文章单独验收

适用于「可以叫我才哥」的公众号技术文章代码区。用户当篇要求优先。这里集中维护规范、实现入口与验收方法，避免从某篇文章的专用脚本反复复制修改。正文、图表和图片排版沿用公众号交付规范。

## 1. 固定要求

| 项目 | 要求 |
| --- | --- |
| 字号 | 实际显示代码文字11px；不能只检查pre/code容器字号 |
| 行高与字体 | 18px；Menlo、Consolas、monospace；Tab显示宽度4 |
| 长行 | 不自动折行，在代码块内部左右滑动；正文不能横向溢出 |
| 代码保真 | 保留字符、缩进、空行和Tab；原始源码单独保存 |
| 高亮 | 按明确语言分词；内联颜色与微信类别标记同时保留 |
| 语言 | data-lang与实际语言一致；仅真正纯文本或未知语言降级使用text |
| 行号 | 默认不生成ul/ol/li；不能靠隐藏行号列表解决占位 |
| 间距 | 代码块上下20px；内部12px；圆角6px |

默认配色：背景`#152C3D`、普通文字`#E6EDF3`、关键字`#D8A5F5`、字符串`#A4DBA1`、数字`#F2B880`、注释`#9BADBE`、函数/内置名称`#8CCBFF`、运算符`#80DAD3`。如当篇换主题，保持可辨认的语法类别和对比度。

## 2. 必须保留的结构

```html
<section class="code-snippet__fix">
  <pre class="code-snippet__js code-snippet_nowrap" data-lang="python">
    <code>
      <span leaf="" style="font-size:11px!important">
        <span class="code-snippet__keyword" style="color:#D8A5F5!important">return</span>
      </span>
    </code>
  </pre>
</section>
```

这是结构示意，不能直接代替完整渲染器：展示用的换行缩进不应加入实际代码文本，必要的宽度、空白、行高等内联样式由脚本生成。

- 外层仅用`section.code-snippet__fix`；不要给section也添加`code-snippet__js`，历史编辑器曾据此重新解析整块并丢失自定义字号。
- pre保留`code-snippet__js code-snippet_nowrap`与真实语言；`overflow-x:auto`，宽度不超过正文。
- 每一行一个code，内部恰好一个完整的`span[leaf]`；高亮片段全部放在leaf里面。**leaf是整行字号层，不是给每个token随意增加的属性。**
- code采用块布局、`width:max-content;min-width:100%;max-width:none`，行高18px。pre、code、token保留pre空白语义并禁止单词强制折行。
- 外层、pre、code、leaf和高亮片段都明确11px；即使微信把code恢复为默认14px，leaf仍可保住其内部文字的11px。字号检查必须落到实际文本节点的父元素。
- 代码区保留`text-size-adjust:none`及webkit前缀作为辅助设置。**它不能替代leaf结构**，先前仅添加这一设置未解决用户手机反馈。
- 高亮类别按词法类别生成：keyword、string、number、comment、function、built_in、operator；不依赖外部CSS或JavaScript完成着色。

## 3. 通用实现

[公众号代码块_v1.0.0.py](公众号代码块_v1.0.0.py)只负责代码区，不处理公众号登录、草稿、图片上传或整篇文章主题。

输入为JSON数组，每项必须包含`language`和`source`。示例见[示例代码_v1.0.0.json](示例代码_v1.0.0.json)。不根据内容猜测语言；Pygments无法识别的语言发出告警并降级text，原文保留。Pygments支持某个语言不代表微信原生引擎也完整支持它，仍以保存后实际效果为准。

```bash
python -m pip install -r requirements_v1.0.0.txt
python 公众号代码块_v1.0.0.py --input 示例代码_v1.0.0.json --output 示例输出_v1.0.0
```

输出三份带版本号的文件：用于插入正文的`代码片段`HTML、用于本地查看的`代码阅读版`HTML，以及包含原始字符串的`原始代码`JSON。重复输出至同一目录会覆盖同版输出，制作新版本应使用新目录。

整篇排版器可以直接加载`render_block(source, language)`，获得一个lxml section元素；或调用`render_html(blocks)`取得HTML字符串。版本文件名不适合普通import时使用以下方式：

```python
import runpy

codeblocks = runpy.run_path("公众号代码块_v1.0.0.py")
section = codeblocks["render_block"]("print('hello')", "python")
```

不要把文章标题、路径、草稿ID、固定代码块数量写入通用模块。Markdown由上游解析器转换，传入原始代码和语言；不要把已经渲染的逐行HTML当作原始字符串再次渲染。

## 4. 源码与显示HTML的关系

Pygments分词结果必须逐字还原输入（显示前只统一CRLF/CR为LF），否则停止生成。用lxml写入文本而非拼接未转义的HTML，避免`<`、`>`、`&`或引号被当成标签。

显示HTML把普通空格换成NBSP，避免微信清洗高亮span之间的空格。空行仍包含一个NBSP占位；不删除末尾空行。Tab原样保留，显示宽度由`tab-size:4`决定。

验收时：把显示NBSP还原为空格，纯空白行按空行核对，其余字符和缩进不变。**这只是显示比对规则，不应用于改写可运行源码**；字符串内部有真实NBSP、纯空白行含空格等情况，应以单独保存的原始代码为准。不要从微信HTML反向生成用于运行的源码。

## 5. 保存与验收流程

1. 本地渲染：逐块核对语言、源码、空行、leaf结构、颜色和11px。
2. 宽窄屏检查：至少1280、390、360px；长行内部横滑，整页不横向溢出。
3. 如任务已授权更新草稿，通过API保存并回读；只修代码时保留正文其他修改、图片、当前封面和裁剪，不用本地旧全文覆盖用户编辑。
4. 有可访问的微信阅读链接时，用登录浏览器只读打开，核对实际文字字号、leaf、颜色、源码和横滑。API回读HTML的本地渲染与微信阅读页是两项不同证据。
5. 用户在手机微信重新预览，分别确认字号、高亮和横滑。编辑器再次保存后可能重写结构，必要时重新核验。

本方案本身不授权更新草稿、发送预览、发表或群发；沿用任务与公众号交付规范已有授权。原创、广告等人工设置放在最后一次正文API更新后复核。

### 本地验收入口

```bash
python -m playwright install chromium

```

已有Chrome时可传`--browser`指定可执行文件，避免重复安装。验收脚本不连接微信、不修改草稿；输出JSON结果及手机尺寸截图。

[代码块验收_v1.0.0.py](代码块验收_v1.0.0.py)检查源码、转义、空行、Tab、未知语言降级、不同宽度、实际文字11px、多类别高亮和触摸横滑。额外模拟code为14px、普通token丢失字号但leaf保留的情况；再移除leaf字号作为负例，确认会检测到14px。该回归模型来自参考文章观察，不声称等同微信内部解析器。

### 微信阅读页的关键检查

对正文代码区遍历真实文本节点，检查其父元素的`getComputedStyle(...).fontSize`，不能只读pre/code的字号。纯文本或单一语法类别不要求多色；高亮检查使用实际计算颜色而非只检查class存在。

```javascript
const fonts = new Set();
for (const pre of document.querySelectorAll('#js_content pre')) {
  const walker = document.createTreeWalker(pre, NodeFilter.SHOW_TEXT);
  let node;
  while ((node = walker.nextNode())) {
    if (node.textContent.trim()) {
      fonts.add(getComputedStyle(node.parentElement).fontSize);
    }
  }
}
console.log([...fonts]); // 应为 ["11px"]
```

此片段仅用于已授权页面的只读检查，不写入文章正文，不采集Cookie、Token或其他账号信息。它只覆盖字号，其余检查仍要完成。

## 7. 避免重走的路径

- 为横滑把所有语言改成text：微信按纯文本处理，高亮会丢失。
- 只加overflow，或只在本地检查：手机仍可能换行。
- 只给普通pre/code/token反复加11px或禁止自动放大：已被用户反馈仍偏大，应优先复用整行leaf结构。
- 外层section加原生代码识别标记：可能触发编辑器重建并丢失样式。
- 行号列表只隐藏：曾出现圆点、占位和代码右移，应直接不生成。
- 保存成功即宣称手机通过：必须区分源码、API、实际阅读页和手机四层证据。
