# 数据分析与可视化

把用户手上的数据，变成**可读、可信、可决策**的洞察与图表。

核心主张：**先有分析意图，再有图表**。图表不是装饰，是"回答某个问题"的视觉论证。宁可少画一张图，也不要画一张读者看不懂或会被误导的图。

## 四条主线

1. **数据概览与清洗**——先知道手里是什么，再谈分析。
2. **统计特征提取**——用稳健的数字刻画分布、关系与变化。
3. **关键指标识别**——把数字收敛到少数几个能驱动决策的指标。
4. **图表匹配与设计**——按意图选图型，按原则打磨细节。

最终交付：**数据洞察摘要 + 对应图表**（附口径说明与边界）。

## 标准工作流

### 第 1 步：接收与对齐

先固定这六件事，缺哪项就明确假设并标出，不要默认：

| 项目 | 要问清的内容 |
|---|---|
| 业务语境 | 这份数据描述什么对象？回答哪个问题？ |
| 规模与粒度 | 多少行多少列？一行代表什么（用户/订单/天/事件）？ |
| 字段语义 | 每个字段是什么、单位是什么、什么口径算出来的 |
| 时间 | 时间范围、时区、粒度（日/周/月）、是否连续 |
| 血缘 | 数据从哪来、经过哪些处理、有没有已知缺陷 |
| 决策 | 这份分析最终要让谁做什么决定 |

用户只给了一份文件、没给背景时，用数据本身推断（列名、值域、粒度），在输出里把推断写成"假设"，请用户确认。**不要因为背景缺失就拒绝分析。**

### 第 2 步：数据概览与清洗

- 读 [references/01-数据概览与清洗.md](references/01-数据概览与清洗.md)。
- 产出**数据体检报告**：规模、字段类型、粒度与唯一键、缺失率、重复率、异常值、口径风险。
- 区分**维度（dimension）**与**度量（measure）**，这是后面选图的输入。
- 清洗走"决策阶梯"：能标不删、能改不猜、每次改动留痕。**任何删除都要写明删除量与理由。**
- 先用脚本跑一遍客观体检，不要靠肉眼：

```bash
python scripts/profile_data.py data.csv --out profile
```

### 第 3 步：统计特征提取

- 读 [references/02-统计特征提取.md](references/02-统计特征提取.md)。
- 单变量：集中趋势 + 离散程度 + 分布形态 + 集中度。
- 双变量：相关系数（按类型选）+ 列联表 + 组间差异（先看效应量）。
- 时序：趋势、季节性、环比/同比、滚动窗口、变化点。
- **偏态数据用中位数和分位数，不用均值**；比率类汇报时说明是加权还是简单平均。
- 每个统计量都要有"所以呢"——它指向什么观察、什么图表。

### 第 4 步：关键指标识别

- 读 [references/03-关键指标识别.md](references/03-关键指标识别.md)。
- 用四层结构收敛：**结果（outcome）→ 驱动（driver）→ 诊断（diagnostic）→ 护栏（guardrail）**。
- 给每个入选指标写清口径：分子、分母、人群、时间窗、实体、维度、排除项。
- 能用恒等式拆解的，一定拆解（例如 `收入 = 活跃人数 × 付费率 × 人均购买次数 × 客单价`）。
- 规模与比率同时出现；比率必须交代分母。
- 宁可 5 个能用起来的指标，也不要 30 个没人负责的指标。

### 第 5 步：图表匹配（核心）

- 读 [references/04-图表匹配.md](references/04-图表匹配.md)。
- 三步定图型：
  1. 这句话想表达的**意图**是什么（比较 / 趋势 / 占比 / 分布 / 相关性 / 层级 / 关联 / 逻辑 / 地理 / 复合）？
  2. 手上字段是**分类、顺序还是数值**？有几个系列、多少个类别、多少个数据点？
  3. 用**视觉通道准确性排序**校验：位置 > 长度 > 角度/斜率 > 面积/体积/密度。
- **一张图只回答一个问题**。标题写结论，不写字段名。
- 数据规模决定图型：类别多、点密集时改用热力图、分面、Top-N + 其他，而不是硬画饼图。
- 可以调用脚本拿一个结构化建议：

```bash
python scripts/suggest_chart.py --spec chart_spec.json
```

- 匹配完必须**反向自检**：这张图会不会误导？见第 6 步。

### 第 6 步：可视化设计与生成

- 读 [references/05-可视化设计原则.md](references/05-可视化设计原则.md)。
- 四个打磨维度：
  - **准确性**：柱状图基线从 0 开始；面积映射到面积不映射到半径；不用 3D 透视扭曲比例；饼图必须构成 100%；图表类型与数据类型匹配。
  - **可读性**：图形元素与背景对比度 ≥ 3:1，小字 ≥ 4.5:1；分类用不同色相，连续值用同色相深浅，正负值用背离配色；控制视觉复杂度；按阅读动线排版。
  - **有效性**：提高数据墨水比，删掉无意义网格与边框；突出重点、弱化次要；标题即结论；图例靠近数据；尊重"时间从左到右""男左女右"等约定；把大数字换算成可感知的尺度。
  - **完整性**：披露数据来源、处理与清洗步骤、概念定义、编码方法、不确定性（置信区间/误差线）、署名与品牌。
- 生成图表时统一走固定样式，保证同一批图风格一致：

```python
from viz_style import setup_style, COLORS, finish
setup_style()          # 中文字体 + 统一配色 + 去掉多余边框
```

- 输出同时保留：图（PNG/SVG）、支撑数据表（CSV）、绘图脚本（可复现）。

### 第 7 步：洞察摘要与交付

- 读 [references/06-洞察摘要与交付.md](references/06-洞察摘要与交付.md)。
- 摘要按**决策报告**结构写，不要只做描述：

```
1. 结论与建议      —— 一句话说明该做什么
2. 量级与影响人群  —— 多大、影响谁
3. 证据与不确定性  —— 哪些图支撑、置信程度如何
4. 因果状态        —— 是事实、相关、预测还是因果
5. 机制与假设      —— 为什么会这样
6. 行动、负责人、预期效果
7. 验证方式与护栏
```

- 每张图配一句图注：**这张图回答什么问题 + 关键读数**。
- 交付清单：洞察摘要、图表、支撑数据、脚本、口径说明、已知局限。

## 运行规则

- 先说结论，再说过程。用户要的是判断，不是流水账。
- **不要编造基准值。** 引用"行业平均留存 40%"这类数字前，必须能给出来源、口径、人群、时间；给不出就写"暂无可靠基准，仅供内部横向比较"。
- 区分**事实 / 相关 / 预测 / 因果**。前后对比图只是诊断，不是因果证据；要下因果结论必须有随机实验或可辩护的准实验设计。
- 展示比率时用加权聚合（`sum(分子)/sum(分母)`），不要对日百分比取平均，除非定义就是这样写的。
- 数据规模小时（n < 100）慎谈相关性，图上看散点，不做显著性叙事；数据规模大时（n > 10 万）不直接画散点，先聚合或抽样。
- 涉及个人隐私、支付、位置、聊天内容时，只做聚合分析，不还原个体身份。
- 用户已有图表时，先按第 5、6 步给出**具体问题清单**（图型是否匹配意图、坐标轴是否截断、配色是否误导、是否缺口径），再给改进版。
- 脚本只是辅助，最终图型与设计判断由分析逻辑决定，不要因为脚本推荐就放弃专业判断。

## 知识边界

本技能的设计原则部分整理自蓝星宇《数据可视化设计指南：从数据到新知》的分类框架与设计准则；分析方法部分整合自游戏数据分析领域的两本专著（《游戏数据分析的艺术》《游戏数据分析实战》）的方法论。两处来源的时代背景与业务语境不同，引用时：

- 书中的具体数值阈值（留存率、付费率、图表尺寸等）只作示例，**不作为当前通用标准**；
- 书中未覆盖现代实践的部分（实验曝光记录、语义层、可观测性、跨端身份、经济系统账本、隐私合规）由本技能补充；
- 涉及软件版本、平台政策、法规要求时，必须另行核对现行官方资料。
