# 方法整合与引用边界

本技能由两类方法整合而成：**可视化设计准则**与**数据分析方法体系**。这份文件说明每部分内容的性质、整合方式，以及引用时需要注意的边界。

## 1. 两类方法的来源与整合

### 1.1 可视化设计准则

这类内容归纳自通行的可视化设计准则与公开研究结论，属于方法论的整理与转述，不来自任何单一出版物：

| 结论 | 原始出处 |
|---|---|
| 位置 > 长度 > 角度/斜率 > 面积/体积/密度的感知精度排序 | Cleveland & McGill, *Graphical Perception* (1984) |
| 按分类型 / 顺序型 / 数值型对视觉通道分别排序 | Mackinlay (1986) |
| 说谎指数（Lie factor）= 图形比例 ÷ 数据比例 | Edward Tufte |
| 对比度要求：图形元素 ≥ 3:1，小字 ≥ 4.5:1 | WCAG AA 级 |
| 数据墨水比理论 | Edward Tufte |
| 圆润饱满形状被认为更美观 | *The effect of aesthetic on the usability of data visualization* (2007) |
| 视觉素养测试（VLAT，12 种可视化类型） | Lee et al. (2016) |
| 常见信息图排版动线（直线 / 蛇形 / 梯子 / 环状） | 信息图排版研究 |

整合后落在本技能中：

- **图表功能分类**（比较 / 趋势 / 占比 / 分布 / 相关性 / 层级 / 关联 / 逻辑示意 / 地理）与各类图表的适用场景 —— 见 `04-图表匹配.md`；
- **七种选图思路**（视觉通道准确性、数据特征、传达信息、发布场景、用户视觉素养、美观度、与主题契合度）—— 见 `04-图表匹配.md`；
- **四个打磨维度**（准确性 / 可读性 / 有效性 / 完整性）—— 见 `05-可视化设计原则.md`。

### 1.3 领域无关化改造

原始方法体系面向游戏产品（移动 / PC / 主机，F2P / 买断 / 订阅 / 广告 / 混合变现），本技能做了如下改造：

1. **指标库改造**：把游戏特有的指标（DAU/MAU、付费率、ARPPU、留存、抽卡、经济系统、服务器、匹配公平）抽象为通用分类（增长与获客、使用与活跃、留存与流失、变现与单位经济、成本效率、体验与质量、公平与信任护栏），保留口径契约与检查规则。
2. **拆解树改造**：保留恒等式思路，把游戏收入拆解替换为通用收入 / 成本 / 价值实现量拆解。
3. **图表视角补充**：分析侧强在"指标与埋点"，弱在"图表选型与设计"。本技能以图表功能分类与四维设计准则补齐这一环。
4. **规模适配补充**：原方法体系未覆盖"不同数据规模下该用什么图表"，本技能新增按行数、类别数、时间点数的适配规则。

## 2. 本技能补充的现代实践

两类来源的年代与业务语境都偏早期，以下内容为本技能补充：

- **数据规模分级策略**（小样本 / 中等 / 大样本 / 超大规模），以及对应的图型切换规则；
- **图表反模式清单**与"反向自检"十问；
- **图表选择速查矩阵**（意图 × 首选 / 次选 / 慎用）；
- **不确定性表达的三种手法**（置信带、误差线、密度表示）；
- **一图一问原则**与结论式标题；
- **交付物清单**与版本物料管理规则；
- **自动化脚本**（数据体检、图表推荐、统一样式）；
- 隐私最小化、地图合规、占位符规范等合规要求。

## 3. 引用边界与免责说明

使用本技能时必须注意：

1. **具体数值阈值只是示例，不是当前标准。** 例如留存率、付费率、对比度之外的尺寸建议、图表宽高比等，都反映写作当时的语境。需要基准时，必须给出来源、地区、口径、人群与时间。
2. **不要引用未经核实的历史结论。** 用于说明设计方法的案例数据不能作为当前事实引用。
3. **软件界面与工具能力会变化。** 涉及 Tableau、ECharts、D3、Adobe Illustrator、ColorBrewer、i want hue 等工具时，具体界面与默认行为以当前官方文档为准。
4. **分析方法的时代差异。** 方法论反映的是较早期的 PC / 移动端发行实践；现代实践中的实验曝光记录、语义层、可观测性、跨端身份、经济系统账本、隐私合规等已由本技能补充，不应把早期做法当作现行最佳实践。
5. **两类来源的业务语境不同。** 可视化设计准则来自通用设计领域，分析方法来自游戏行业。迁移到金融、医疗、政务等强监管领域时，需要额外核对行业规范与法规要求。
6. **本技能不替代专业判断。** 脚本给出的图表建议是基于规则的辅助，最终选型必须结合具体分析意图、受众与交付载体来决定。
