### 领域无关化改造

原始技能面向游戏产品（移动/PC/主机、F2P/买断/订阅/广告/混合变现），本技能做了如下改造：

1. **指标库改造**：把游戏特有的指标（DAU/MAU、付费率、ARPPU、留存、抽卡、经济系统、服务器、匹配公平）抽象为通用分类（增长与获客、使用与活跃、留存与流失、变现与单位经济、成本效率、体验与质量、公平与信任护栏），保留口径契约与检查规则。
2. **拆解树改造**：保留恒等式思路，把游戏收入拆解替换为通用收入/成本/价值实现量拆解。
3. **图表视角补充**：原始技能强在"指标与埋点"，弱在"图表选型与设计"。本技能以《数据可视化设计指南》的九分类框架与四维设计准则补齐这一环。
4. **规模适配补充**：原始技能未覆盖"不同数据规模下该用什么图表"，本技能新增按行数、类别数、时间点数的适配规则。

## 3. 本技能补充的现代实践

两处来源的年代与业务语境都较早期，以下内容为本技能补充：

- **数据规模分级策略**（小样本/中等/大样本/超大规模），以及对应的图型切换规则；
- **图表反模式清单**与"反向自检"十问；
- **图表选择速查矩阵**（意图 × 首选/次选/慎用）；
- **不确定性表达的三种手法**（置信带、误差线、密度表示）；
- **一图一问原则**与结论式标题；
- **交付物清单**与版本物料管理规则；
- **自动化脚本**（数据体检、图表推荐、统一样式）；
- 隐私最小化、地图合规、占位符规范等合规要求。

## 4. 引用边界与免责说明

使用本技能时必须注意：

1. **书中的具体数值阈值只是示例，不是当前标准。** 例如书中出现的留存率、付费率、对比度之外的尺寸建议、图表宽高比等，反映的是写作当时的语境。不得把它们当作今天的行业基准。需要基准时，必须给出来源、地区、口径、人群与时间。
2. **不要引用未经核实的历史结论。** 书中引用的历史案例数据（如某年的进出口额、疫情数字）仅用于说明设计方法，不能作为当前事实引用。
3. **软件界面与工具能力会变化。** 书中提到的工具（Tableau、ECharts、D3、Adobe Illustrator、ColorBrewer、i want hue 等）的具体界面与默认行为可能已经改变；实施时必须核对当前官方文档。
4. **分析方法的时代差异。** 两本游戏数据分析专著反映的是较早期的 PC/移动端发行实践。现代实践中的实验曝光记录、语义层、可观测性、跨端身份、经济系统账本、隐私合规等，已由本技能补充，不应把书中的旧做法当作现行最佳实践。
5. **不同来源的业务语境不同。** 可视化设计原则来自通用设计领域，分析方法来自游戏行业。把它们迁移到金融、医疗、政务等强监管领域时，需要额外核对行业规范与法规要求。
6. **本技能不替代专业判断。** 脚本给出的图表建议是基于规则的辅助，最终选型必须结合具体分析意图、受众与交付载体来决定。
