# 03 关键指标识别

一份数据里能算出上百个数字，但一份分析只该有 **3–7 个关键指标**。这一步的任务是把数字收敛成"能驱动决策"的少数几个。

## 目录

1. 从目标到问题
2. KPI 四层结构

## 1. 从目标到问题

**拒绝**模糊目标，把它改写成可回答的问题。

| 模糊目标 | 改写后的问题 |
|---|---|
| 提升业绩 | 业绩变化来自人变少、转化降低、购买频次下降，还是单价下降？ |
| 提高用户活跃 | 哪个来源的用户在哪个环节没有形成稳定的使用习惯？ |
| 优化内容 | 哪些内容带来持续使用，而哪些只带来短期时长虚增？ |
| 降低成本 | 哪部分成本在增长，是量增长还是单位成本上升？ |
| 看板做点东西 | 这个看板要支持哪三个决策？每个决策缺的信息是什么？ |

**规则**：写不出一句可回答的问题，就还没到选指标的阶段。

## 2. KPI 四层结构

把指标分成四层，**不要混用角色**。

| 层级 | 作用 | 特征 | 例子 |
|---|---|---|---|
| **结果 Outcome** | 业务与用户获得的价值 | 滞后、少而稳 | 收入、留存、毛利、满意度 |
| **驱动 Driver** | 团队能实际影响的杠杆 | 可干预、可归因 | 转化率、下单频次、客单价、成功率 |
| **诊断 Diagnostic** | 定位驱动为什么变化 | 分维度、分环节 | 各渠道转化、各步骤流失、各品类单价 |
| **护栏 Guardrail** | 防止局部优化伤到全局 | 与驱动反向制衡 | 投诉率、退款率、崩溃率、成本率 |

三个硬约束：

1. 每个**结果**至少配一个**驱动**（否则无法行动）。
2. 每个有风险的**驱动**至少配一个**护栏**（否则可能被不当优化）。
3. "崩溃率""可用性"这类通常是**护栏或驱动**，不是业务结果，不要放在顶层。

## 3. 北极星与北极星体系

好的北极星指标：

- 代表**真实获得的价值**，不是曝光或点击这类过程量；
- 定义稳定、可审计、可复算；
- 变化足够频繁，能指导日常动作；
- 难以在不创造真实价值的情况下被"刷"上去；
- 能被拆成团队自己可控的驱动；
- 与长期健康（留存、口碑、成本）同向。

**一个指标藏住重要权衡时，用小型体系：**

| 角色 | 作用 | 示例 |
|---|---|---|
| 主价值指标 | 核心价值实现量 | 每周完成核心行为的用户数 |
| 规模/频次指标 | 防止只服务少数人 | 覆盖人数、人均频次 |
| 体验/公平护栏 | 防止伤害体验 | 投诉率、失败率、退款率 |
| 商业护栏 | 防止不可持续 | 单位成本、毛利率、现金回收周期 |

北极星不是"最大的那个数"，而是"最能代表我们要创造什么价值的那个数"。

## 4. 恒等式分解

**能用恒等式表达的，一定要写出来。** 恒等式的好处是：任何一个数变化，都能被拆成明确的几个因子，而不是靠猜。

### 收入

```text
收入 = 有效人群 × 付费转化率 × 人均购买次数 × 次均净额
```

再加上其他收入项（订阅、广告、增值、服务费），并显式处理退款、税费、渠道分成、汇率。

### 活跃人群

```text
期末活跃人群
= 上期留存人群 + 本期新激活人群 + 回流人群 − 本期流失人群
```

注意：这个恒等式是概念性的，**必须先用不重叠的时间窗定义每一部分**再计算，否则会重复计数。

### 价值实现量

```text
价值实现量 = 有效人群 × 参与率 × 人均成功次数
```

### 成本

```text
总成本 = 固定成本 + 变动成本
变动成本 = 业务量 × 单位变动成本
```

### 使用方式

1. 先破解变化：收入环比降了 10%，是人群少了、转化降了、频次少了，还是单价降了？
2. 每一项再往下拆一层，直到落到可执行的动作。
3. **区分"恒等式"与"业务假设"**：恒等式是数学关系（一定成立）；"人均购买次数提高会带来更高留存"是假设，需要验证，要标注出来。

常见错误：用两个互相重叠的口径解释同一个变化（例如用"DAU 和活跃用户"互相当原因），结果是自己解释自己。

## 5. 指标字典契约

**绝对不能只用指标名当定义。** 每个进入交付的指标都要写全：

| 字段 | 内容 |
|---|---|
| 指标 ID | 稳定英文标识 |
| 名称 | 中文名 + 英文/缩写 |
| 层级与领域 | 结果/驱动/诊断/护栏 + 业务域 |
| 业务问题 | 支持什么决策 |
| 定义 | 自包含的自然语言描述（不看名字也能算出来） |
| 公式 | 分子、分母、聚合方式 |
| 人群与排除 | 谁在分母里、排除了谁 |
| 实体与粒度 | 用户/订单/会话/日/设备 |
| 时间 | 口径锚点、时间窗、时区、日界 |
| 维度 | 允许下钻的维度 |
| 数据来源 | 权威表/字段 |
| 数据策略 | 去重、迟到、回补、零分母 |
| 金额口径 | 币种、汇率、含税/不含税、退款 |
| 方向与目标 | 越大越好还是越小越好，目标来源 |
| 护栏 | 与该指标配套的制衡指标 |
| 负责人与时效 | 谁维护、刷新频率 |

**分母检查**：分母必须包含分子。`付费率 = 付费用户 / 活跃用户`，活跃用户必须包含所有付费用户。

**零分母策略**：分母为 0 时不要输出 0 或无穷，应输出"无数据"并说明。

## 6. 候选指标筛选打分

从所有能算出来的指标里，按六个维度打分（1–5 分），加权排序：

| 维度 | 问的问题 |
|---|---|
| 决策相关性 | 这个数变化了，会有人改变动作吗？ |
| 可行动性 | 团队能影响它吗？影响路径清楚吗？ |
| 口径稳定性 | 换个分析师能算出一样的结果吗？ |
| 数据就绪度 | 数据源可靠、有负责、有测试吗？ |
| 信噪比 | 变化能反映真实信号而不是随机波动吗？ |
| 抗操纵性 | 会不会被短期手段刷上去而伤害长期？ |

**落地规则**：

- 先上"能闭环的最小集合"：每个指标都必须有人、有动作、有可信来源。
- 没有负责人、没有对应动作、没有稳定来源的指标，直接延后。
- 指标要分阶段：先上最小集，成熟后再加。

## 7. 常见领域的指标候选

只作选择库，不是清单，按业务实际取用。

### 增长与获客

曝光 / 点击率 / 安装转化 / 激活率 / 注册率 / 单客获取成本 / 首次价值达成率 / 达到首次价值用时 / 自然量占比 / 各渠道留存活率

### 使用与活跃

日活/周活/月活 / 活跃比（DAU÷MAU 之类） / 新用户占比 / 人均会话数 / 人均使用时长（中位数 + 分位数） / 核心行为参与率 / 核心行为成功率 / 功能使用广度 / 并发峰值

### 留存与流失

精确日留存 / 滚动留存 / 区间留存（**三者不可互换**） / 生存曲线 / 流失率 / 回流率 / 流失半衰期

留存必须说明口径锚点：首次安装、首次注册、首次使用还是首次付费。

流失的判定阈值要从**实际使用节奏**推导，不要套用固定的 7 天 / 30 天。

### 变现与单位经济

付费转化率 / 人均收入 / 付费用户人均收入 / 购买频次 / 客单价 / 首次付费率与用时 / 复购率与间隔 / 价格档位与 SKU 结构 / 付费集中度 / 退款与拒付 / 收入口径（流水 / 确认收入 / 净收入三者务必分开）

```text
付费转化率 = 付费实体数 / 有效实体数
人均收入 = 期间收入 / 有效实体数
客单价 = 有效购买额 / 有效订单数
```

单位经济：CAC、留存期、贡献毛利、回收周期、LTV/CAC 比值。**不要把"收入 ÷ 广告花费"叫 ROI**，那是 ROAS；ROI 要扣投资并说明是增量口径。

### 成本效率

单位变动成本 / 毛利率 / 履约成本率 / 人工投入产出 / 库存周转 / 坏账率

### 体验与质量

成功率 / 失败率 / 错误率 / 响应时延（P50 与 P95 一起看） / 可用性 / 中断率 / 首次响应时间 / 满意度 / 净推荐值 / 投诉率

时延类指标**必须用分位数**，均值会掩盖尾部体验。

### 公平与信任护栏

权益公平度 / 群体间差异 / 强制消费与误操作投诉 / 数据与隐私合规风险 / 违规处理时效

## 8. 指标体系验收检查

交付前逐条过：

- 每个结果指标都有至少一个可控驱动。
- 每个有风险的驱动都有至少一个护栏。
- 每个指标的分子、分母、实体、时间、币种口径一致且自包含。
- 规模与比率同时出现，比率都交代了分母。
- 领先指标（早期信号）与滞后指标（结果）都有。
- 没有明显的重复计数（同一群体被两个互不独立的指标重复解释）。
- 假设、预测、因果推断都做了标注，并写明了验证方式。
- 每个关键指标都能追到具体的图表与数据来源。
- 明确写出"本期不上"的指标及原因。

## 检查清单

- 目标是否已改写成可回答的问题？
- 有没有把护栏指标放到顶层当结果？
- 北极星是否代表真实价值而不是过程量？
- 能用恒等式的指标拆分了吗？
- 每个指标的口径是否自包含（六项齐全）？
- 分母包含分子吗？零分母怎么处理？
- 留存类型、收入口径、ROAS/ROI 区分开了吗？
- 指标数量是否收敛到能闭环的最小集合？
- 是否列出了本期不上的指标及理由？
