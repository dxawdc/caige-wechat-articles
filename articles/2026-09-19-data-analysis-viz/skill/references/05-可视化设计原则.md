# 05 可视化设计原则

打磨一张图表，看四个维度：**准确性、可读性、有效性、完整性**。前两个是底线（不能错、要能读），后两个是上限（能不能说服人、能不能被信任）。

## 目录

1. 数据的准确性
2. 设计的可读性
3. 传达的有效性

5. 落地参数与实现

## 1. 数据的准确性

**可视化的第一要求是如实反映数据。** 以下四类是最常见的误导性设计。

### 1.1 随意改变尺度

**典型表现：人为截断坐标轴。**

同一份数据，把柱状图的纵轴起点从 0 改成 20，数值之间的差距看上去就会被拉大很多。读者往往不会注意坐标轴的玄机，只记住了一眼看到的印象。

**规则：**

- **柱状图、面积图的基线必须为 0**。因为读者通过长度/面积感知数值，截断会直接扭曲比例。
- **折线图允许非零基线**（数据远离 0 时从 0 开始反而抹平变化），但必须明确标注轴范围，并在需要时加注说明。
- 更严重的错误是让图形尺寸与数值完全不成比例（如柱子的高度与数据不符），这已经属于造假。

### 1.2 面积、体积与长度的混淆

用圆面积呈现数值时，数据应当映射到**面积**，而不是**半径**。

```text
圆面积 = π × r²
```

如果把 1:2 的数据映射到半径，实际画出的面积比会变成 1:4，差异被夸大了一倍。

**实现要点：**

- 有些工具（如 Illustrator 的圆）输入值直接对应面积，无需处理。
- 有些工具（如 D3、matplotlib 的 `s` 参数、大多数散点气泡）需要你指定半径或面积参数——**务必确认参数语义**。matplotlib 的 `scatter(s=...)` 接收的是面积，仍是常见踩坑点。
- 手工换算时，先对数据开方再作为半径输入。

### 1.3 不恰当的数据映射与图表选择

每种图表都有适用前提，违反前提的图即使能画出来也是无效的。

| 错误 | 问题 | 正确做法 |
|---|---|---|
| 饼图的数据不构成 100% | 占比图的前提被破坏 | 改柱状图 |
| 折线图没有时间变量 | 趋势图需要一个有序维度 | 改柱状图 |
| 散点图用了分类变量 | 分类变量不该映射到连续通道 | 分类用颜色/形状 |
| 面积图表现分类变量 | 同上 | 分类用颜色 |
| 双轴图轴范围随意调整 | 制造或抹平两个系列的同步感 | 标注轴范围理由，或用上下对齐双图 |

### 1.4 3D 与透视

3D 透视会降低人对数值的感知精度，使差异被不必要地夸大或缩小。

Edward Tufte 提出的"说谎指数"（Lie factor）：

```text
说谎指数 = 图形上的比例关系 ÷ 数据上的比例关系
```

正常图表的说谎指数应在 1 附近。3D 透视效果图的案例中曾测得高达 14.8。

**规则：**

- 统计图表默认用 2D。**不要用 3D 柱状图、3D 饼图。**
- 3D 只在这些情况使用：数据本身具有空间属性（地形、流场、体积）、需要交互探索大规模多维数据、或明确以审美为目的的艺术可视化。
- 用 3D 时要在设计要求里明确"数值精度让位于空间表达"。

### 1.5 相似外观但含义不同的图表

这几对图表外观相似，实则是完全不同的分析目的，务必区分：

| 图表对 | 区别 |
|---|---|
| 柱状图 vs 直方图 | 柱状图比较**类别**；直方图展示**区间频数分布**，柱子紧贴 |
| 折线图 vs 密度图 | 折线图表达**趋势**；密度图表达**分布** |
| 饼图 vs 环图 | 同为占比，环图中心可放总量标签 |
| 玫瑰图（按高度） vs 玫瑰图（按角度+高度） | 后者会把差异放大更多，需明确说明 |

**玫瑰图的特别提醒**：它有放大数据差异的天然倾向，且不同工具默认的编码方式不同（有的按扇形高度、有的同时按角度）。用它时必须说明编码方式，并判断是否适合当前数据。

## 2. 设计的可读性

### 2.1 颜色

**背景色**

- 默认白色 / 黑色；想减轻刺激可用米白、深灰。
- 避免大红大绿这类浓烈颜色作背景，会增加阅读难度。
- 想做出辨识度可以用品牌色作背景（如《金融时报》的粉橘色），前提是不影响可读性。

**对比度**（依据 WCAG 的无障碍建议，AA 级）

| 元素 | 最低对比度 |
|---|---|
| 图形元素与背景 | 3 : 1 |
| 小字（数据标签、图例、轴标签） | 4.5 : 1 |
| 大号文字 | 3 : 1 |

配色完成后用对比度检测工具验证。

**按数据类型选配色：**

| 数据类型 | 配色方案 | 说明 |
|---|---|---|
| 分类数据 | **不同色相**（红、绿、蓝…） | 色相差异大才便于区分类别 |
| 连续数值 | **同色相明度渐变**（浅绿 → 深绿） | **深色 = 大值，浅色 = 小值**，方向不能反 |
| 含正负值 | **背离配色**（蓝—白—红） | 白色对应 0；负值越大越蓝，正值越大越红 |
| 顺序数据 | 同色相渐变或分级的顺序色阶 | 顺序要与数据顺序一致 |

**其他约束：**

- 色盲友好：避免红绿单靠色相区分，配合明度或形状差异。工具（如 ColorBrewer）可开启 colorblind-safe 选项。
- 打印友好：保证灰度打印后仍可区分。
- 不同文化对颜色含义理解不同（白色在欧美婚礼、在中国传统丧事中含义相反），面向跨文化受众时要检查。

### 2.2 视觉复杂度

- 图表元素过多、线条互相缠绕、扇形过密，都会让图不可读。
- **饼图的分类太多**是最典型的低可读性情形——小扇形完全无法阅读，此时应改用柱状图。
- 多系列折线超过 5 条时，线条重叠严重，应改为小倍数分面或高亮一条。
- **控制信息量是设计者的责任**，不能把所有数据都塞进一张图。
- 多个图表并存时，要考虑**阅读动线**：直线形、蛇形、梯子形、环状等排版大多遵循线性顺序且视觉对称，更符合阅读习惯。避免让读者的视线来回跳跃。

### 2.3 字体

- 文字元素（标题、轴标签、数据标签、图注）的可读性同样重要。
- **在目标设备上测试**：同一张 16:9 的图，在电脑上很大，在手机上很小。
- **径向图表中的文字朝向**要特别处理：
  - 默认让文字正对圆心的做法会让下半圈文字倒置（如 225°、270°、315° 位置）。
  - 更好的做法：**对称旋转**（上半天顺时针、下半天逆时针），保证都大致从左到右阅读；
  - 或者**始终水平摆放**文字，只让位置沿半径延伸。
- 中文字体要显式设置，否则会出现方框乱码。

## 3. 传达的有效性

### 3.1 提高数据墨水比

"数据墨水"指图中真正承载数据的墨水。绘图者应把墨水用在必要的地方，**删掉删除后不影响信息传达的元素**。

常见可删除项：

- 没有意义的灰色背景、渐变填充
- 数据已有标签时多余的网格线
- 不必要的三维边框、阴影、装饰线条
- 重复的图例与轴标签

**注意：** 删减的前提是不损失必要信息。有数据标签才删网格线；没标签就别删。

### 3.2 突出层次

让主要信息跳出来，次要信息退回去：

| 手法 | 用法 |
|---|---|
| 颜色对比 | 主要信息用高饱和高明度（如亮红），次要信息用低饱和低明度（如灰） |
| 尺寸差异 | 重要元素大，次要元素小 |
| 加背景/装饰 | 给关键区域加底色块、边框 |
| 注释线 | 用引线标出关键点 |
| 明暗与运动 | 区分关键信息的位置与动效 |

应用时注意：**只突出一个重点**。多个元素同时被突出等于没有突出。

### 3.3 提供总结和引导

- **把主要发现凝练成标题**，让读者一眼看到中心主旨。好的标题写结论（"三线城市留存显著高于一线"），差的标题写字段（"各城市留存率对比"）。
- 提供图解和注释，把图讲清楚。
- **有引导的图表**会告诉读者该看哪里、结论是什么；**无引导的图表**只做了整体描摹，读者得自己去寻找结论。
- 图例尽量**靠近数据**，避免读者在图例和图形之间来回切换；能用直观图标代替文字说明更好。

### 3.4 尊重约定俗成的习惯

| 习惯 | 要求 |
|---|---|
| 时间方向 | 从左到右、从上到下；**不要反向排列时间轴**——读者不细看轴会把趋势读反 |
| 位置习惯 | 如"男左女右"这类约定；先左后右、先上后下 |
| 颜色含义 | 性别常用蓝/红；积极话题用明亮暖色，消极话题用灰暗冷色 |
| 文化差异 | 同一颜色在不同文化中含义可能相反 |

强行违背这些习惯会显著增加理解成本，甚至造成误读。

### 3.5 重视数据的接近性

"接近性"指受众在多大程度上觉得这份数据与他/她相关。

**内容层面：**

- 优先选与目标受众贴近的数据（面对上海读者，上海本地数据比全国平均更有贴近感）。
- 过于小众或过于私人的数据难以与读者建立联结。

**表达层面：** 人对大数字的理解能力有限（亿、兆、光年几乎无法感知）。把抽象数字换算成可感知的尺度：

| 抽象 | 具象 |
|---|---|
| 含糖量 39g | 约等于 10 块方糖 |
| 录取率 1.7% | 平均要打败 59 个人 |
| 内存占用 2.3GB | 相当于 500 首歌 |

**降低抽象程度**：单元可视化（一个小圆代表一个人）比 100% 柱状图更能让人感受到"具体的人"。

### 3.6 保持沟通的连贯性

呈现一系列图表时，传达过程类似"讲故事"，需要有起承转合。

1. 明确有哪几个**故事点**。
2. 理清它们之间的逻辑关联：递进 / 并列 / 转折 / 因果 / 升华。
3. 串成一个意义通顺的序列。
4. 展示顺序、高亮强调、排版布局都为这个序列服务。
5. 需要时用动画转场衔接（静态交付时，用"关键帧 + 说明"代替）。

## 4. 信息的完整性

**完整披露是可信度的来源。** 在图表传播几轮之后，读者往往已经不知道源头。以下六项应当披露。

| 披露项 | 内容 | 为什么重要 |
|---|---|---|
| **数据来源** | 谁发布、何时发布、链接或渠道；自采集要说明采集方法、样本量、时间范围 | 判断可靠性与时效性 |
| **数据处理方法** | 筛选、转换、取数规则；模糊值如何确定化；缺失与异常值如何处置 | 让别人能复算，也能看出你是否做了手脚 |
| **概念解释** | 抽象指标如何构成（如"幸福指数"由哪些维度合成） | 保证结论透明可核 |
| **数据编码方法** | 新颖或容易歧义的编码方式（如玫瑰图按高度还是按角度） | 否则读者会读错 |
| **不确定性** | 预测给区间不给点；相关性给置信带；比较给误差线 | 展示严谨性，避免过度自信 |
| **作者信息** | 署名、Logo、水印 | 可追溯性 + 知识产权保护 |

**缺失值与异常值的处置尤其要说清。** 举例：如果某年的数据存在异常值，直接保留会让该年均值失真，直接删除又会让剩余数据无法反映真实水平。可选的做法是：

1. 不汇报这一年的结果，并说明原因；
2. 从其他可靠数据源补数据，但**必须验证口径一致**（把新数据与现有数据中不缺失的部分做对比）；
3. 做敏感性分析，同时给出保留与剔除两种结果。

无论选哪种，都要在图表脚注里写明。

### 不确定性的三种常见视觉表达

| 手法 | 适用 |
|---|---|
| 置信带（带状区域） | 趋势预测、回归线的不确定性；随时间推移变宽 |
| 误差线 error bar | 分组比较中各类别的均值波动范围；同时看出"最稳"和"最不稳"的类别 |
| 密度/热力表示 | 多人选择结果的分布，深浅代表聚集程度 |

图上有误差线时，可以在图注里点明：哪个类别值最高、哪个类别不确定性最大。这比单独一条柱子有信息量得多。

## 5. 落地参数与实现

### 5.1 统一出口

一批图必须风格一致，否则读者会在"配色代表什么"上反复重新学习。做法是把样式抽成一个模块：

```python
from viz_style import setup_style, COLORS, finish

setup_style()                       # 中文字体、字号、去掉上右边框
fig, ax = plt.subplots(figsize=(8, 5))
# ...绘图...
finish(fig, "结论式标题", df, metrics={...})   # 统一标题、署名、导出 PNG/SVG/CSV
```

### 5.2 本账号约定（"可以叫我才哥"）

| 元素 | 约定 |
|---|---|
| 中文字体 | Microsoft YaHei（备选 Noto Sans CJK SC / SimHei / PingFang SC） |
| 主色板 | `#188568` `#4878B7` `#E59B42` `#9566AA` `#CB6677` `#5D9FAD` |
| 网格 | 只保留 `whitegrid` 纵向参考，去掉上右轴线 |
| 图内署名 | 图下角标注"模拟数据 / 数据来源 · 可以叫我才哥 · 版本" |
| 涨跌配色 | 中国习惯：**涨用红色、跌用绿色**（与欧美相反） |
| 货币 | 默认 ¥ |
| 分辨率 | PNG 150–170 dpi，同时导出 SVG 供放大 |
| 数据表 | 每张图配套导出 CSV（utf-8-sig，便于 Excel 打开） |

### 5.3 常见技术坑

| 问题 | 处理 |
|---|---|
| 中文显示为方框 | 显式设置 `font.sans-serif` 与 `axes.unicode_minus=False` |
| 负号显示为方框 | `rcParams["axes.unicode_minus"] = False` |
| 气泡尺寸不对 | `s` 参数是面积，不是半径 |
| SVG 中文字体缺失 | 导出时 `svg.fonttype = "path"`，把文字转成路径 |
| 长标签被截断 | 换行、缩短、或改用水平条形图 |
| 手机上看不清 | 减少类别、放大字号、拆图 |

## 检查清单

**准确性**

- 柱状图/面积图基线是 0 吗？
- 面积类图表映射到的是面积而不是半径吗？
- 有 3D 透视吗？如果没有空间属性，删掉。
- 饼图数据构成 100% 吗？类别 ≤ 5 吗？
- 图表类型与数据类型匹配吗？

**可读性**

- 图形与背景对比度 ≥ 3:1、小字 ≥ 4.5:1 吗？
- 分类用不同色相，连续值用同色相渐变，正负值用背离配色吗？
- 颜色方向对吗（深 = 大）？
- 有信息过载吗（类别太多、线条缠绕）？
- 中文字体设置了吗？手机尺寸下能看清吗？

**有效性**

- 删掉无意义网格和边框了吗？
- 重点只有一个吗？
- 标题写的是结论还是字段名？
- 图例离数据近吗？
- 时间轴方向符合习惯吗？
- 大数字换算成可感知的尺度了吗？

**完整性**

- 数据来源、时间、链接写了吗？
- 清洗与筛选步骤披露了吗？
- 缺失值/异常值怎么处理的写了吗？
- 特殊编码方式说明了吗？
- 不确定性（区间/误差线/置信带）表达了吗？
- 署名或来源标识加了吗？
