## 1. 接收清单

拿到数据先补全下面这张表。缺项可以推断，但必须写成"假设"而不是当成事实。

| 项目 | 要确认的内容 | 缺失时的处理 |
|---|---|---|
| 对象 | 一行代表什么（用户/订单/日/事件/设备） | 看唯一键与列名推断，标注假设 |
| 粒度 | 时间粒度、空间粒度、实体粒度 | 从时间列的最小间隔推断 |
| 规模 | 行数、列数、时间跨度 | 直接读 |
| 单位 | 金额币种、数量单位、比率分母 | 看列名与量级，不确定就问 |
| 口径 | 每个指标怎么算出来的 | 标记为待确认，分析时用保守表述 |
| 边界 | 是否含测试账号、机器人、员工、退款、异常期 | 检查是否有标记列；没有则说明风险 |
| 血缘 | 上游系统、加工链路、已知缺陷 | 记录，影响结论强度 |
| 决策 | 谁会因为这份分析做什么决定 | 影响图表与摘要的详略 |

## 2. 结构体检

按顺序做，不要跳步：

1. **规模**：行数、列数、时间跨度、覆盖实体数。
2. **字段类型推断**：不要相信文件里的类型标记，按值重新推断。
   - 整数 / 浮点 / 布尔 / 日期时间 / 分类 / 自由文本 / 标识符
   - 注意"长得像数字的分类"：邮编、行政区划码、用户 ID、订单号
3. **唯一键与粒度**：找一组能唯一标识一行的字段。
   - 找不到唯一键 → 说明存在重复或粒度不纯，必须先解决
   - 发现粒度混层（同一列里既有汇总行又有明细行）→ 拆开或过滤
4. **时间字段**：确认时区、是否连续、有无缺失日期、有无跨年。
5. **标识符列**：ID 类字段不参与统计，但用于去重和关联。

## 3. 维度与度量

这一步决定后面的图表选择，必须显式做。

| 类型 | 特征 | 判定 | 常见图表用法 |
|---|---|---|---|
| **分类维度** | 取值是标签，无序 | 唯一值少（一般 < 50）、不可比较大小 | 分组轴、颜色、分面 |
| **顺序维度** | 有内在顺序 | 等级、区间、月份、年龄段 | 有序轴、渐变配色 |
| **时间维度** | 时间戳或时间标签 | 有间隔规律 | 横轴 |
| **数值度量** | 可加减、有单位 | 连续或计数 | 纵轴、尺寸、颜色深浅 |
| **高基数标识** | 唯一值 ≈ 行数 | 用户 ID、订单号 | 只用于去重与关联 |
| **自由文本** | 长字符串、高基数 | 备注、评论 | 需先做主题/情感编码 |

判断技巧：

- 唯一值数量 vs 行数：比值 > 0.9 且无明显重复 → 标识符；比值小 → 分类。
- 数值列要问：**这个数能相加减吗？** 分数、比率、排名不能直接相加。
- 有单位的数值要记录单位，图注和摘要都要带单位。

## 4. 质量体检

逐项量化，不要只说"有缺失"。

### 缺失

- 每个字段的缺失数与缺失率。
- **区分缺失类型**：
  - 完全随机缺失 → 可插补，代价较小
  - 与自身值相关（如高收入者不填收入）→ 插补会引入偏差，宜标记后单独分析
  - 结构性缺失（某段时间某平台整体没有）→ 是数据链路问题，先修流程
- 关键字段缺失会导致后续所有口径失真，优先处理。

### 重复

- 完全重复行数。
- 业务键重复（如同一订单出现多次）：要判断是脏数据还是正常的多次事件。
- 不是所有重复都要删：一条订单多次支付尝试是真实业务，不能去重。

### 异常值

用三种方法交叉验证，不要只依赖一种：

1. **统计法**：IQR 法（超过 Q1−1.5×IQR 或 Q3+1.5×IQR）或 MAD 法（偏态数据更稳健）。
2. **业务法**：值域是否超出物理可能（年龄 1000 岁、金额为负、百分比 > 100%）。
3. **关系法**：字段间矛盾（结束时间早于开始时间、分项之和 ≠ 合计）。

**关键判断：异常值是错误，还是尾部真实业务？**

- 输入错误、单位混用 → 修正
- 真实的极端用户/大客户/长尾 → **保留**，用中位数和分位数汇报，或单独分层说明
- 无法判断 → 保留但标记，做敏感性分析（剔除前后各算一遍）

### 一致性

- 同义异写：`上海` / `上海市` / `SH` / `沪`
- 编码不一致：日期格式混用、数字存成文本（含千分位、单位后缀）
- 单位混用：同一列里既有元又有万元
- 大小写、全半角、前后空格
- 时区混用：部分行 UTC、部分行本地时间

### 完整性

- 时间序列有无断档（缺失的日期不是缺失值，是没数据）
- 分类维度有无遗漏（对照业务全集检查）
- 关联键能否对上（左表有多少行在右表找不到）

## 5. 清洗决策阶梯

**从代价最小、信息损失最少的一步开始，逐级上升。**

| 级别 | 动作 | 适用 | 要求 |
|---|---|---|---|
| 0 | 原样保留 + 标记 | 不确定是否异常 | 新增标记列，不改变原值 |
| 1 | 标准化 | 格式、编码、单位、空白 | 有明确映射规则 |
| 2 | 修正 | 明确的输入错误 | 记录修正规则与影响行数 |
| 3 | 插补 | 少量缺失、缺失类型随机 | 说明方法（均值/中位数/前值/模型）与比例 |
| 4 | 剔除行 | 关键字段缺失、确认的脏数据 | 报告剔除量与占比，做敏感性对比 |
| 5 | 剔除列 | 极高缺失率（经验阈值 > 60%）或全常量 | 说明理由 |

**通用约束：**

- 每一步都留痕：改了什么字段、改了多少行、依据什么规则。
- 清洗前后各跑一次关键统计量，看结论有没有翻转。
- 不要把清洗和业务过滤混在一起。业务过滤（只看某渠道、某版本）是分析范围，属于分析决策，要在口径里写清楚。
- **永远保留一份原始数据副本**，所有清洗在副本上做。
- 汇总口径的比率不要跨层重算（不要拿分平台的付费率再做一次简单平均）。

## 6. 口径对齐

同名字段在不同团队含义可能完全不同，必须落到具体定义。

需要对齐的常见歧义：

- "活跃用户"：登录算吗？前台停留算吗？有最短时长门槛吗？
- "留存"：精确日留存 / 滚动留存 / 区间留存，三者不可互换
- "收入"：流水 / 确认收入 / 净收入（扣税、平台分成、退款）
- "付费率"：分母是活跃用户、安装用户还是注册用户
- "转化率"：漏斗哪一步到哪一步
- "环比"：对比上一个同等长度周期，还是上一个周期
- "新用户"：首次安装、首次注册还是首次付费

对齐动作：

1. 把每个关键字段写成一句自包含的定义，**不能只用指标名当定义**。
2. 分子、分母、人群、时间窗、实体、排除项六项齐全。
3. 检查分母是否包含分子（如"付费率"的分母必须是包含付费用户的更大群体）。
4. 检查漏斗是否严格嵌套，不嵌套的步骤不能画成漏斗。
5. 检查占比之和是否为 100%（不构成整体时不能用饼图/百分比堆叠图）。

## 7. 按数据规模调整策略

| 规模 | 行数 | 策略 |
|---|---|---|
| 小样本 | < 200 | 逐条看；不做显著性叙事；用表格 + 散点图为主；每个点都可追溯 |
| 中等 | 200 – 5 万 | 标准流程；直方图/箱线图看分布；散点图直接画 |
| 大样本 | 5 万 – 100 万 | 先聚合再画；散点改密度/热力图/抽样；注意类别基数爆炸 |
| 超大规模 | > 100 万 | 数据仓库侧聚合；只把聚合结果与抽样样本带到图表；注意聚合粒度与时间窗 |

列数维度：

| 列数 | 策略 |
|---|---|
| < 10 | 可以全字段体检，图表可以多系列 |
| 10 – 30 | 先按重要性筛，分组呈现，必要时降维 |
| > 30 | 先做字段相关性聚类/降维/选出代表性字段，不要一张图塞所有列 |

### 二、字段清单

## 检查清单

- 粒度说清楚了吗（一行代表什么）？
- 有没有把标识符当分类维度用？
- 缺失、重复、异常都说清数量了吗？
- 异常值是错误还是真实业务，判断有依据吗？
- 清洗规则留痕了吗，删除量报了吗？
- 每个关键字段的口径自包含吗（不看指标名也能算出来）？
- 分母包含分子吗，占比之和是 100% 吗？
- 清洗前后的结论有没有翻转？
