## 核心口径与结果

- S44 由用户确认按2026-07-01起过滤，仅排位；实际记录07-03至09-13，快照截至09-14。
- 332场，187胜145负，56.3%胜率；MVP含胜败，77次=胜方37+败方40，23.2%。
- 用户确认初始钻石IV1星（刻度56），最终荣耀51星（刻度151），净增95。原始首条赛后钻石IV2星保持不变。
- 逐局累计升227、掉132，`56+227-132=151`。每日净值35天正、4天0、8天负；`108-13=95`。34天曾出现掉星对局，不等于34天净掉星。
- 3连分析主口径：每段首次达到3场连续胜/负后的下一局，每段计一次。3连胜后16/25胜（64%），3连败后13/16胜（81.25%）。
- 滚动交叉口径：最近3场全胜后33/58胜，全败后16/19胜。长连续段会贡献多个触发点，两口径不能混为同一个分母。
- 全赛季金26、银34，合计60；仅98场完整详情的牌子分布为金8、银12、铜7、未获牌71。铜牌不能按332场推断完整总数。
- 332场评分完整，平均8.41、中位数8.3，79场至少10分；最高14.4（后羿17/1/11），最低2.9（姜子牙0/1/1），两项各1场，并列极值在代码中全部保留。
- 19张静态PNG、19张SVG、1个段位GIF；正文21张图片=19张静态图+GIF+海报。净星数不再重复画累计曲线或每日台账。

## 从本机采集开始

```bash
python -m pip install -r requirements_采集_v1.0.0.txt

python 分析_v1.2.0.py --input 本人分析输入_v1.0.0.csv --mapping 段位映射证据_v1.1.0.json
```

替换自己的ADB、设备标识（`adb devices`查看）与APK路径。采集依赖MuMu内本人已登录会话、对应APK，以及已开放的App数据读取权限；不自动开root、安装证书或修改代理。省略`--collect`只探测首批。新采集请用新目录。

协议仅在王者营地10.114.0826验证，客户端接口不保证长期稳定。会话只在内存中使用。采集器源协议曾真实执行；参数化版本做语法检查，未为了文章再采一次全量线上数据。最小请求间隔0.85秒，网络异常有限重试；本次40页到`hasMore=false`。

清洗入口从相邻`采集状态_v1.0.0.json`读取本人角色标识以关联牌子详情；如果这份元数据不在，可传入`--role-id`。未取得本人详情编码时保留缺失，不用其他选手的牌子代替。模式会去掉组队后缀；评价优先详情`matchDesc`，否则用列表`desc`。省略详情时，不能复现完整详情牌子分布或保证评价统计与本文一致。

## 统计解释

1. MVP率=含胜败MVP的对局数/全部对局，所有组别采用一致口径。获胜局MVP率37/187是另一个指标。
2. 历史段位按App枚举还原。`roleJobName`在本批数据全部荣耀王者，不采用。满星边界可能重合，首次晋级另检查段位编码。
3. 逐局段位推定为赛后，初始1星由本人确认；每日净变化按北京时间结算日，对局习惯按开局日。
4. 总账相符，不证明每场额外星数的机制。07-06王昭君失败后+1保留原值作为待核验记录；未猜测保护或奖励原因。
5. 三连触发只用下一局之前的信息；不能先挑选已结束的3连胜段，否则“下一局必败”是筛选偏差。序列可跨天、间隔其他模式；没有控制队友、英雄、段位或休息。
6. 3连分析仅观察下一局，不代表后续是否发生整段连败。区间为描述性Wilson95%，没有处理时序相关性；个人小样本不能证明匹配机制或构成上分建议。
7. 332场核心字段完整，98场有完整详情、234场缺详情。伤害经济不作全赛季平均；缺少铜牌不能填成无牌。
