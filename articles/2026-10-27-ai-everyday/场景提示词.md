# 普通人用AI：36个场景提示词

版本：1.1.0。按自己的资料、目标和运行环境改写。

## 01｜对话查询：把不懂的地方问明白

我第一次接触这个概念。请用一个生活例子解释，再给一个实际例子。遇到专业词先说明含义，最后问我两个问题，检查我有没有理解。

适合试用：DeepSeek、豆包、Kimi、ChatGPT、Claude、Gemini。先挑自己方便使用的一个，重点看它能否听懂你的背景，能否在追问中把解释说清楚。

## 02｜联网搜索：查到答案，也查到出处

查一下这款工具目前能否导出可编辑 PPTX。优先使用官方帮助文档，注明页面日期；把已确认、需要实测和没找到依据的内容分开写。

适合试用：DeepSeek、Kimi、ChatGPT、Gemini 中实际提供搜索功能的入口。结果里有链接，也仍要判断链接是否直接支持结论。

## 03｜专题研究：把分散资料整理成一张知识地图

围绕新手买咖啡豆，按产地、处理工艺、烘焙程度、风味和杯成本建立研究提纲。先给研究问题，再查资料，价格与产品信息标明日期。

适合试用：Kimi 的研究与材料处理功能、Gemini Deep Research、ChatGPT 的相关研究功能。最后检查引用、比较维度和资料缺口。

## 04｜学习与备考：让解释、练习和反馈连起来

我每天能学习 40 分钟，请基于这份大纲安排两周计划。每天包含一个知识点、一道练习和一次复习；先出题，等我回答后再解释。

适合试用：豆包、DeepSeek、Kimi、ChatGPT、Gemini；需要实际操作软件时，再搭配能够使用相应工具的 Agent。

## 05｜生活规划：行程、菜单、购物清单都能整理

帮我安排两天的城市游，带老人同行，每天最多两个主要地点，减少往返。列出路程、休息时间和雨天替代方案，需要实时确认的信息单独标明。

适合试用：豆包、DeepSeek、ChatGPT、Gemini，按任务开启搜索或图片理解能力。

## 06｜讨论与决策：帮自己看见遗漏和取舍

这是我的方案。请先复述目标，再分别从用户、执行者和维护者角度提出问题。比较两个可行方向，说明取舍，最后列出三个最需要先验证的假设。

适合试用：DeepSeek、Kimi、Claude、ChatGPT。

## 07｜写文档：从零散想法到完整方案

根据这些笔记写一份项目方案，包含目标、使用者、主要流程、分工和验收标准。缺少的信息写“待补充”，先给提纲，再完成可编辑文档。

适合试用：DeepSeek、Kimi、Claude、ChatGPT；需要直接交付文件时，可以结合 WorkBuddy 等支持相应文件操作的工具。

## 08｜改文档、审文档：把表达和逻辑一起理顺

检查这份文档的重复、矛盾和未定义术语。先列问题与位置，再修改；保留所有数字和关键结论，输出修改后的文件与简短变更说明。

适合试用：WorkBuddy、Kimi 的文档功能、Claude、ChatGPT；直接修改文件的能力取决于使用入口和授权。

## 09｜阅读长文：摘要之外，还能对照和追问

对照这两份报告，按主题列出一致点、差异和新增内容。每项附原文页码或段落位置；扫描不清、无法确定的内容不要猜。

适合试用：Kimi、Claude、ChatGPT、Gemini 中支持相应格式的文件入口。

## 10｜做 PPT：从材料到能讲清楚的一组页面

用这些材料做一份 8 页项目汇报，听众是第一次了解项目的同事，汇报时间 10 分钟。每页一个重点，数据注明来源，输出可编辑 PPTX 和讲稿。

适合试用：Kimi PPT、WorkBuddy、Gamma。官方功能说明提供了生成或编辑演示稿的路径，具体导出效果仍需打开文件检查。

## 11｜处理 Excel：合并、去重、匹配和公式

合并这些月报，保留来源文件名。先列出字段差异和重复记录，再按我确认的规则处理；输出汇总表、异常清单和核对结果。

适合试用：WorkBuddy、Kimi 的表格功能、ChatGPT 的文件与数据处理能力；复杂批处理也可以用编程 Agent 写脚本。

## 12｜数据分析：围绕问题找证据

先检查数据质量，再分析销售额变化来自哪些产品和地区。区分数量与价格影响，给出计算过程和汇总表；无法从数据证明的原因标成待验证假设。

适合试用：支持运行代码与处理文件的 ChatGPT、WorkBuddy，或 Codex、Claude Code 等编程 Agent。模型能解释统计概念，不代表它已经实际算过。

## 13｜数据可视化：让结果更容易看懂

用这份数据做两张图：一张比较各地区销量，一张展示月度趋势。标清单位和时间范围，保留可编辑源文件，并说明每张图回答什么问题。

适合试用：能运行 Python、生成网页图表或操作表格的 Agent。真实数据图应该根据数据绘制，再检查坐标和口径；概念插画不能代替计算。

## 14｜写公众号：从选题到排版形成完整流程

阅读这些项目资料，先列可写入文章的事实，再给提纲。用我的口吻写作，不补造经历；完稿后检查标题、正文、配图和来源是否对应。

适合试用：DeepSeek、Kimi、Claude、ChatGPT 参与写作，WorkBuddy 或其他 Agent 配合资料、图片和排版文件处理。

## 15｜内容复用：一份材料，换成适合不同渠道的表达

将这份复盘改成 800 字文章摘要、6 页 PPT 提纲和 60 秒视频脚本。分别适配阅读、汇报和观看场景，保留同一套事实，不增加新结论。

适合试用：DeepSeek、Kimi、Claude、ChatGPT；文件和视频成品再结合对应制作工具。

## 16｜会议与沟通：把讨论整理成行动

把这份会议记录整理成决定事项、行动项和待确认问题。每个行动项列负责人和时间，没有明确的信息留空；最后起草一封简短跟进邮件，先供我审阅。

适合试用：支持音频转写的工具，加上 Kimi、DeepSeek、Claude、ChatGPT 或 WorkBuddy 整理文稿；发送前自行审阅。

## 17｜画图：把脑中的画面变成可讨论的方案

为一篇介绍咖啡入门的文章画一张插画：桌面上有手冲器具和笔记，暖色、干净，上方留标题空间。先给整体方向，再按反馈调整。

适合试用：豆包、即梦、ChatGPT 图像工具、Adobe Firefly。不同入口适合的尺寸、参考图和编辑方式，以实际功能为准。

## 18｜改图：明确保留什么、改变什么

保留角色的脸型、服装和姿势，只将背景换成咖啡店。主体边缘保持自然，留出标题区域；完成后说明改动范围。

适合试用：即梦的智能画布与编辑功能、豆包改图、ChatGPT 图像工具、Adobe Firefly。

## 19｜制作宣传物料：把一张图扩展成一套用途

以这张已确定的主视觉制作图标、横版封面和竖版宣传图。沿用角色和配色，分别构图，列出尺寸清单，并检查缩小后是否还能看清主体。

适合试用：图像生成与编辑工具，配合 Agent 检查尺寸和整理交付文件。平台最新规格需要单独核对。

## 20｜生成视频画面：让文字和图片动起来

用这张咖啡店插画生成短片：保持人物外貌和场景结构，蒸汽缓缓上升，镜头轻微推进。不要新增人物和文字，先做一个可用片段。

适合试用：即梦、Runway 等有视频生成能力的产品。即梦官网明确提供文生视频和图生视频入口。

## 21｜用代码做动画：需要精确修改时很实用

做一条解释数据增长的动画，先列时间轴，再写代码渲染。标题、数字和颜色用参数控制，保留源码，检查字幕和图形是否重叠。

适合试用：Codex、Claude Code、WorkBuddy 等能够执行代码的 Agent，配合 Canvas、Three.js、Remotion、Manim 或 Blender 等实际渲染工具。

## 22｜制作完整宣传视频：脚本、素材、声音一起组织

用这些真实游戏录屏做一条 30 秒宣传片。先交脚本和分镜，再剪辑；只展示已有玩法，配旁白和字幕，输出横竖两个版本并检查裁切。

适合试用：通用模型写脚本，视频工具生成片段，Agent 配合剪辑、字幕和导出工具完成成片。

## 23｜配音、音乐和音效：给作品补齐听觉体验

为这段解说生成清晰自然的配音，标出多音字读法；另做轻柔背景音乐。分别交付音轨，混音时让旁白清楚可听，不要出现突然的音量变化。

适合试用：具备语音合成、音乐或音效功能的创作平台。例如 Adobe Firefly 官网列出了语音、音乐和音效相关功能；实际音频处理还可由 Agent 调用工具完成。

## 24｜3D 建模：从参考图走向可编辑模型

根据参考图先做基础模型，输出正面、侧面、背面预览和可编辑源文件。先核对比例，再处理材质灯光，列出与参考仍有差异的部分。

适合试用：支持 3D 生成的工具，或能够连接 Blender 的 Agent。我的相关尝试包括 Blender 与 Lux3D 路线。

## 25｜桌面宠物与角色动画：把形象变成可交互作品

用这套角色素材做一个桌面宠物，先支持待机、被点击和睡觉三组动作。背景透明，可以拖动和缩放，检查是否遮挡操作，并保留可修改的动作资源。

适合试用：图像工具制作与修改角色，编程 Agent 配合桌面框架完成交互，必要时用动画工具处理动作。

## 26｜开发网站：把资料做成别人也能用的页面

做一个手机也能看的作品集网站，展示我提供的 6 个项目。先交本地可运行版本，检查图片、链接和按钮，再列出上线需要完成的步骤。

适合试用：WorkBuddy、CodeBuddy、TRAE、Codex、Claude Code、Cursor，按需要配合托管与数据库服务。

## 27｜开发微信小程序：把常用功能带到手机里

做一个活动资料查询小程序，先实现列表、搜索和详情。用测试数据运行，检查空列表、加载失败和手机页面，最后给出真机验证清单。

适合试用：编程 Agent 配合微信开发者工具。模型生成代码与平台审核通过是不同阶段。

## 28｜开发手机 App：从自己的一个需求开始

做一个供我自己测试的 Android 记录应用，先支持新增、查看和修改记录。说明数据保存位置，生成测试安装包，并验证退出重开后的数据和权限行为。

适合试用：CodeBuddy、TRAE、Codex、Claude Code、Cursor，配合 Android Studio 或相应移动开发工具。

## 29｜开发桌面软件：把常做的小事变成按钮

做一个批量重命名小工具，可选择文件夹、预览新名称、处理重名冲突，确认后执行。输出可运行程序和源码，并验证中文路径。

适合试用：编程 Agent 配合 Python 桌面框架、Electron 等实现方式。选择哪一种，跟功能和运行环境有关。

## 30｜开发小游戏：先把一局核心体验做完整

做一个合成小游戏，第一版只实现掉落、碰撞、合成和失败重开。交付可试玩版本，说明规则，并列出需要我重点测试的操作。

适合试用：TapTap 制造等创作平台，或编程 Agent 配合相应游戏引擎。发布和后续维护仍要按平台流程处理。

## 31｜搭建信息系统：把采集、整理和阅读串起来

基于这些已授权来源做一个信息整理原型，保留标题、日期、来源和原文地址。去重后分类，生成可追溯的摘要，并展示失败任务与重试入口。

适合试用：编程 Agent 帮忙建设系统，通用模型处理文本，数据库和调度程序负责保存与运行。

## 32｜浏览器和手机自动化：让重复操作按步骤执行

在这个演示页面按条件筛选记录，提取名称与链接并形成表格。每一步确认页面状态，遇到登录、验证码或意外跳转先停下并说明。

适合试用：带浏览器工具的 Agent，或 Agent 配合 Playwright；手机端使用实际支持设备和应用的自动化工具。

## 33｜文件与电脑事务：把规则说清楚再批量处理

先统计这个目录的文件类型、大小和重复情况，给出整理方案与新路径预览。保留原始来源映射，确认后按规则处理，输出结果清单。

适合试用：WorkBuddy、Codex、Claude Code 等具有相应文件与命令执行能力的 Agent，具体权限以环境为准。

## 34｜定时任务：让重复工作按时进行

每天北京时间 9 点检查这些来源的新内容，整理摘要并保留链接。只有新增内容或执行失败时提醒我；创建后展示时间、运行条件和验证结果。

适合试用：支持定时任务的 Agent，或者由编程 Agent 配置实际调度程序。能否后台持续运行，取决于工具与部署环境。

## 35｜制作 Skill 和工作流：把好方法留下来

把这次已验证的方法整理成可复用技能，写清适用场景、输入、步骤、输出和验收。加入一个示例，遇到不满足条件的任务先说明差异。

适合试用：支持技能或可复用指令的 Agent。先验证一次完整过程，再整理规范，比一开始就设计很复杂的流程更容易落地。

## 36｜持续迭代：修问题、补功能、再验证

先根据日志和复现步骤定位原因，给出最小修改方案。修复后重测出问题的流程和相关功能，说明改了哪些文件、如何验证，以及还有什么未确认。

适合试用：CodeBuddy、TRAE、Codex、Claude Code、Cursor 等编程 Agent，配合日志、测试工具与真实设备。
